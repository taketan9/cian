# cian-gui（Electron 版）ロードマップ

`cian-core` の上に、Chromium で描くもう1つのフロントエンド。端末版（`cian-tui`）は
生き続け、winit + wgpu の `cian-gui` は凍結する。

**この文書は「これから」だけを持つ。** 2026-08-31 に 1295 行・見出し90個まで積み上がり、
新しい「いま」を上に足し続けた結果、同じ文書が2つ溶接された形になっていた。直した
ものの一覧は `git log` にある（この repo のコミットメッセージは長い）。ここに残すのは
**次に手を動かす人の判断を変えるもの**だけ。

---

## この計画が存在する理由

**見た目ひとつ。** 速度は 2026-08-24 に解けた（`want_cpu_renderer` の自動判定）。
残っていたのは「会社の Windows で文字が残念」で、原因は cian の**どちらの描画経路も
OS の文字描画を使っていない**ことだった。Chromium は Windows で DirectWrite を使う。

**2026-08-25、実機で判定が出た。** 3つ並べて、Electron 版は `cian.exe`（「昭和の
コンピュータっぽい」）より明らかに読みやすく、日本語も潰れない。以後の投資はこの1点の
実測に立っている。

## 起動のしかた

```
gui/run.bat        Windows
gui/run.sh         Mac / Linux
```

Electron の場所は探しにいく（`$CIAN_ELECTRON` → `gui/electron.txt` の1行 → リポジトリの
隣の配布版 → `node_modules`）。**見つからないときは、どこを探したかを言って落ちる。**
エンジンが無いときも同じで、空の窓を見せない。`gui/engine.js` は 隣 → target/release →
target/debug の順で探し、**新しい方が勝つ**。

**エンジンを触ったら `cargo build -p cian-server`。** `cargo test` は bin を更新しないので、
古いエンジン相手に「直っていない」と読むことになる。

## 設定 ── 窓が何を読むか

`init.lua` は端末版と**共用**（`%USERPROFILE%\.config\cian\init.lua`、
`CIAN_CONFIG_DIR` で置き場所を変えられる）。ただし読む項目は端末版と同じではない。
エンジンの `settings` が返すもの（`crates/cian-server/src/main.rs`）:

- **`cian.set_option` から**: `home` `editor` `shell` `view` `key_hints` `edit_style`
  `show_hidden` `tab_width` `lang` `notify` `notify_min_secs` `preview` `transfer_limit`
- **あるかないかだけ**（メニューの行を出すかの判定に使う）: `cian.ai` /
  `cian.snippets` / `cian.ssh` / `macro.lua`。端末版の `menu.rs` も同じ3つを訊いて、
  答えが no の行を出さない
- **`cian.set_keymap` の全部**（端末版と同じ表を読む ── 片方で効いて片方で効かない
  束縛は、1つの名前を着た2つのプログラム）
- **Lua が拒んだもの**（`config_errors`）も返して画面に出す。出さないと、init.lua の
  打ち間違いが「黙って無いだけの設定」になり、人は違う所を探しに行く

**窓が自分で決めたことは `state.toml`**（端末版の状態ファイルそのもの）に入る ──
`theme` の隣に `gui_look` `gui_editor` `gui_font` `gui_view` `gui_hints`
`gui_main_pct` `gui_panes_pct`。**`theme` は共用なので、窓で選んだ配色で端末版が開く。**
`gui_font` を `font_level` と分けてあるのは、あちらが端末エミュレータの
ポイント数で、こちらが窓のピクセル数だから（1つの名前に2つの意味を持たせない）。

**`init.lua` は書き換えない。** あれは手で書かれ、コードとして読まれるファイルで、
書き換えるプログラムは人のコメントを整形し直すことになる。

## 毎回通す検査

**画面を見ずに直すと必ず失敗する。** Taketan の 2026-08-30 の言葉:「全般的に、全然
完成度が低い」── 原因は画面を見ずに直していたこと。

1. **`node gui/drive.js`** ── CDP で本物の窓に本物のキーを送る。**基準は例外 0 件。**
   先に `pkill -f "Electron.app/Contents/MacOS/Electron"; sleep 1`（前のプロセスが
   ポートに残ると `the window never appeared` や無関係な ReferenceError が出る）。
   `list` で開いているシートの行を全部読み上げ、`shot:名前` で
   `$TMPDIR/cian-shots/名前.png` に撮る。砂場に自分の config を切るので実設定は汚れない
2. **拡大スクリーンショット**（`clip: {…, scale:3}`）── CSS の後勝ち、`hidden` な見出しが
   空白帯として場所を取る、シェルが panel の 1/3 しか使っていない、ビューアのヒント行が
   一覧のキーのまま ── どれもこれでしか見つからなかった
3. **`python3 scripts/audit.py`** ── 「きれいです」が基準
4. **`cargo test -q --workspace` / `cargo clippy -q --workspace --all-targets -- -D warnings`**
5. **`python3 scripts/requests.py`** ── `gui/REQUESTS.ja.md` の21行。**lint ではなく契約。
   落ちたら直す前に訊く**
6. **`python3 scripts/keycover.py`** ── ヘルプが名前を挙げるキーのうち drive.js が一度でも
   押した割合（14/72）。壊れていた `Ctrl+E` と vim 流の `Ctrl+C/X/V` はどちらも
   「一度も押していない」側にいた
7. **`python3 scripts/parity.py`** ── 端末版と窓版が同じものを同じ言葉で呼んでいるか

CI は Rust 3-OS ＋ front-end ジョブ（`node --check gui/*.js` ＋ 3〜7 のうち Rust 以外）。
**drive.js は CI に無い**（画面と Electron が要る）ので押す前に手で回す。

**検査に checks を足したら必ず変異テストする。** 実際に5回、「指摘が消えた」ではなく
「検査が黙った」をやっている。壊れた版を仕込んで指摘が出ることを確かめ、戻す。

## 繰り返し出たバグの型（足す前にこれを疑う）

1. **書いたのに届かない。** 実装があり、ヘルプにも載り、どこからも実行できない。
   **修飾キー付きは修飾なしより前に置く**（if/else の鎖は上から効く）。素の1文字キーには
   `bare`（!ctrl && !meta）ガード。足したら drive.js で**そのキーを押す**
2. **監査が黙る。** 指摘が消えたのか検査が死んだのか、出力は同じ → **変異テスト**
3. **CSS の後勝ち・UA 負け・親の重なり文脈。** `hidden` はブラウザ既定の `display:none`
   なので `.row{display:flex}` に負ける。**親に z-index が無いと子は親の層に閉じ込められる**
   → 拡大スクショ。`getBoundingClientRect` で矩形を測り、`elementFromPoint` で
   「本当に最前面か」を訊く
4. **測る対象を間違える。** `measureCell()` がシェルの**外**の行間を測って、12行入る場所に
   「7行」と PTY に教えた → **実物と同じ条件で測る**（同じ class のプローブ）。
   時機を推測せず `ResizeObserver` で箱の変化そのものを見る
5. **道具の報告が観測を隠す。** drive.js の LOOK がシェル行をビューア行より優先していて、
   動いている F3 が「効かない」と読めた → **「効かない」の前に道具の報告経路と相手の
   ビルドを疑う**
6. **移植の物差しを1つしか当てていない。** 「辞書差ゼロ」で済んだ気になっていた。
   物差しは `mouse.rs` の当たり判定登録・`Popup` enum・`MenuItem` enum・`ToggleId`・
   **`MenuItem::label` の日本語** → **次元ごとに機械で数える**
7. **画面に出たことがないコードは、間違っていても誰も気づかない。** `hintsNow()` に
   ビューアの枝が丸ごとあったのに `drawHints()` は `say()` からしか呼ばれず一度も
   描かれず、しかもその枝は `style === 1`（vim）でメモ帳の行を返していた
   → **状態を持つ変数は1つの扉にする**（`setViewerOn()`）。足したら `shot:` で撮る

### 挙動の深さ

### リモート ── 2026-09-02 に**実際に通した**

**手元にサーバが無い、がずっとの障害だった。無かったのは発想の方。**
`sshd` と `sftp-server` は macOS にも Linux にも最初から入っていて、
**管理者権限なしで** 127.0.0.1 の空きポートに自分専用のものを立てられる。
`python3 scripts/remote.py` がそれを毎回立てて、通して、片付ける。

立てた日に出たもの:

- **ローカル→リモートの `c` が、手元にコピーして「1件コピーしました」と
  言っていた。** リモートペインの `cwd` は接続前のディレクトリのままなので、
  行き先が手元の適当な場所になる。**サーバは一度も触られない。**
  zip の件と同じ型で、今日これで4件目
- **鍵で入れなかった。** `Target` はパスワードだけを持っていた ──
  なのに `examples/ssh.lua` は前から「鍵認証を使ってください」と書いていた。
  **無い機能を勧めていた**
- 入れたもの: ローカル↔サーバの `c`/`m`（進捗は同じバー）・サーバ内の移動・
  サーバ間の中継（一時ファイルは必ず消す）・**同一サーバの移動は rename**
  （中継すると全バイトが往復し、rename の原子性も失う）

`:chmod` は前からリモートに届いていた（今日初めて確かめた）。

**2026-09-02 の続きで、リモートは仕上げた。** `scripts/remote.py` が本物の
サーバ相手に **21 項目**を通す:

- 鍵で入る／ローカル↔サーバ／サーバ↔サーバ（中継・同一ホストは rename）
- **ディレクトリごと**（`plan_upload`/`plan_download` が木を歩き、親から順に
  mkdir する。**これは端末版にも無かった** ── 両方ファイルだけ送っていた）
- サーバ内の移動・chmod・作成・改名・**中身ごと削除**
- リモートのファイルを開いて書き戻す
- **転送レートの上限が実際に効く**（400KB を 200k/s で 2.03秒、上限なしで 0.08秒）
- AI の走査はリモートペインで断る

リモートが*モーダルなブラウザ*だからで、窓版のリモートは*ペイン*。行き先は

## 決めていないこと

**端末版の全部を持っていくのか。** GUI の相手は「メンバー」で、端末版の相手は Taketan
自身。この非対称は既定文法（vim / メモ帳）で一度採用している。同じ理屈が効くかも
しれないもの:

- **マクロ**（`@` / `q`）── 玄人向け
- **SSH / リモートペイン**（SFTP）── 玄人向け、かつ `cian-server` に SFTP を持ち込むと
  C のビルドが復活し、**社内で Rust を触るときの敷居が数GB上がる**
- **AI** ── 端末版にあるものをそのまま持っていくか
- **git / svn** ── 使う人がいるかで決まる

**急がなくてよい。** ただしどこかで決めないと `cian-server` の依存が膨らんで、
オフライン持ち込みの前提（いまは 14MB の zip 1個）が変わる。
