# まっさらチェック

`itsumono-check` は**壊れていないか**を見る（動くか・死にコードが無いか・
名前が散らかっていないか）。こちらは**壊れていないものの質**を見る。

この二つは物差しが違う。前者が全部緑でも、トグルの補足文が型どおりだったり、
日本語のときだけ列がばらけていたり、権限で断られたのに理由が画面に無かったり
する ―― **2026-09-10 に本人から出た指摘は、全部その側**だった。

## まず、道具が動くことを確かめる

```bash
git log -1 --format='%h %s'
cargo build --bin cian-tui -p cian-server
/tmp/tuienv/bin/python -c "import pyte" || { rm -rf /tmp/tuienv; python3 -m venv /tmp/tuienv; /tmp/tuienv/bin/pip -q install pyte; }
```

**`/tmp` の venv は腐る。** macOS の掃除が `pyvenv.cfg` を先に消すと、
`python` は動くのに `import pyte` だけが落ちる ── `python -m venv` を上書きで
走らせても壊れた site-packages が残るので、`rm -rf` してから作り直す。

**これを飛ばして3ラウンド失ったことがある。** 彼は `cargo run` を使うので、
編集をまたいだセッションでは編集前のビルドを触っている。「直っていない」と
言われたら、まず `:version`（版・git SHA・`-dirty`）を訊く。CI の成果物で
試しているなら、**どの zip か**を訊く。

## ① 台帳を作る ―― 「全機能」を記憶で並べない

一つずつ触るには、**一覧が要る**。頭の中の一覧は必ず抜ける。機械に出させる:

```bash
python3 scripts/keycover.py     # ヘルプが挙げるキー（押されたことがある割合）
python3 scripts/requests.py     # 依頼の台帳
python3 scripts/parity.py       # 端末版と窓版で同じものが同じ言葉で呼ばれているか
python3 scripts/configcover.py  # init.lua の設定を、窓版がいくつ読んでいるか
python3 scripts/settingscover.py # 設定画面が、cian の設定のどこまでを触れているか
```

**設定画面は放っておくと嘘をつく。** 本人の心配（2026-09-11）:「実装とずれた
設定画面になっていないか心配だ」── もっともで、その日のうちに `ssh.lua` の
行き先を間違えている。**画面に出ないものは、無いことにされる** ── cian が
読む設定は `Options` の 20 個だけではなく、キー割当もブックマークもマクロも
テーマもある。`settingscover.py` は `cian.*` の API 13 個と `:where` の
ファイル7つを数え、**画面が触るか、どこで直すかを画面が言っているか**を見る。
出さないものには理由を書く。

`keycover.py` の 73 種のキー、コマンドパレットの一覧（`palette::command_list`）、
メニューの項目（`MenuItem`）、トグルの行（`toggle_rows`）―― この4つが「全機能」
の外周だ。

## ①' 全部叩く（`scripts/sweep.py`）

```bash
/tmp/tuienv/bin/python scripts/sweep.py                  # コマンド 151 個を一つずつ
/tmp/tuienv/bin/python scripts/sweep.py --keys           # マニュアルのキーを一つずつ
/tmp/tuienv/bin/python scripts/sweep.py --monkey 400     # 乱数で 400 手（種は --seed）
/tmp/tuienv/bin/python scripts/sweep.py --list           # 一つずつ結果を出す
/tmp/tuienv/bin/python scripts/sweep.py theme du         # 名前を指定して
node gui/drive.js --commands                             # 窓版の辞書 179 個を全部打つ
```

**窓版も叩く。配布は窓版一本**なので、触ったことのない道はそのまま人の手元へ
行く。窓版で見るのは **`例外 0 件`** だけでいい ── 中身の良し悪しは端末版の
掃引と `parity.py` が見ている。**同じことを二つの道具に見させると、片方を
直したときもう片方が黙る。**

## ①'' 猿（`--monkey`）

掃引は「マニュアルが名前を挙げているもの」しか触れない。**思いつかなかった
組み合わせは永久に残る**。だから乱数で叩き続けて、三つだけ見る:

* **落ちないか** ── サーバ相手の道具が落ちるのは、いちばん高い故障
* **桁が崩れないか** ── 日本語でしか出ない
* **戻れるか** ── Esc を何度押しても出られない面に入らないか

**種を出す。** 崩れたら `--seed` で同じ順を打ち直せる ── 再現できないバグは、
直したかどうかも確かめられない。

一つについて五つ見る ── **㋐反応** ㋒桁 **㋓迷子**（`unknown command` と
言われないか）**㋔Esc で戻るか** **㋕生存**。

**既定は「一つ触るたびに立て直す」。** 使い回すと前のものの状態が残り、
次のものの結果がそれに化ける ── 78 個のキーを続けて押した回、10 個が
「反応なし」に出て、立て直して押し直したら 8 個は動いた。`gg` は直前の
`Shift+U` で既に先頭にいただけ、`Space` は `..` の上でマークを断られて
いただけだった。速さが要るときだけ `--fast`。

**掃引そのものが3回、自分に騙された**（全部この skill の教訓になっている）:

| 騙され方 | 直し方 |
| --- | --- |
| 状態行の返事が消えないので、同じ返事を返す verb が並ぶと「反応なし」に見えた | 毎回 `:pwd` で**目印**を置いてから測る |
| `:` を開く前に打ち始めて、`r`（リネーム）が先に効いた。**測るつもりのものを測っていなかった** | プロンプトが開いたことを確かめてから打つ |
| 砂場の名を `cian-tui-denied-` にしたので、`denied` が常に画面にあった | 検査が探す語を、検査の砂場に名づけない |

**触れないものは数に出す。** 外部エディタ・OS の関連付け・相手の要る通信・
マウス・kitty 拡張が要る綴り ── 「危ないから飛ばす」ではなく「この道具では
見られないから飛ばす」と書き、**別の見方があるならそれも書く**。黙って
飛ばすと、走っていないものを「通った」と読む。

**反応が無くても、壊れているとは限らない。** `QUIET_OK` / `BACK_OK` /
`KEY_CONTEXT` に理由を書く ── 消すのではなく、**なぜ指摘しないのか**を残す。

**数を数える検査には下限がある。** `keycover.py` が 72 → 2 種に落ちたまま
百分率を出し続けたことがある（窓版を `tr()` に通した回）。**急に減ったら、
直ったのか検査が壊れたのかを確かめる。**

## ② 触る ―― 本物の端末と、本物の窓で

```bash
pkill -f "Electron.app/Contents/MacOS/Electron"; sleep 1
/tmp/tuienv/bin/python scripts/tui-drive.py     # 端末版を**本物の pty で**
node gui/drive.js                                # 窓版（例外 0 件が基準）
```

好きな手を打つときは:

```bash
/tmp/tuienv/bin/python scripts/tui-drive.py -- T j j Enter   # 最後の画面も出る
node gui/drive.js , T ? Esc
```

一つの機能について見るのは、いつもこの4つ:

| | 見るもの | 外すと何が起きるか |
| --- | --- | --- |
| ㋐ 出るか | 押して、何かが変わるか | 「書いたのに届かない」（修飾キーの順、`bare` ガード） |
| ㋑ 言葉 | 出た文が、cian の声か | 型どおりの補足文。英語しか言えない知らせ |
| ㋒ 桁 | 列が揃っているか、枠が閉じているか | **日本語でしか出ない**。英語は字数＝桁数 |
| ㋓ 断られたら | 失敗が、理由つきで見えるか | 「エラーに気づきにくい」 |

**㋐ を状態で判断しない。** `report.on === true` で「出た」と3ラウンド言い
続けて、実際はシートがエディタの裏に開いていたことがある。窓版は
`drive.js` の `top:<css>`（`elementFromPoint` がその面を返すか）、端末版は
画面の文字そのものを読む。

## ③ 細部の三つの物差し

```bash
python3 scripts/kotoba.py --list   # 言葉（型どおり・英語しか言えない・ダッシュ）
python3 scripts/widths.py --list   # 桁（字数で測っているところ）
python3 scripts/audit.py           # 死にコード・重複・名前の割れ
```

### ㋑ 言葉 ―― 「AI っぽい」の正体

規則は誰かの好みではなく `crates/cian-tui/src/theme.rs` の `tr()` の doc
コメントにある。**そこに書いてあるのに、機械が見ていたのは句点だけ**だった
（`nothing_cian_says_ends_in_a_full_stop`）。`kotoba.py` が残りを見る:

* **ダッシュでつないだ一文** ―― doc がいちばん長く説明している規則。
  「〜です。〜できます」の2文にする。doc が悪い例として挙げている
  `unsaved changes — Ctrl+S saves` は、その日本語版が `mouse.rs` にそのまま
  生きていた
* **英語しか言えない知らせ** ―― 端末版の既定は日本語なのに、`self.message`
  には `copy failed: {}` `backup failed, not saving` が並ぶ。**失敗の知らせ
  ほどここに多い**。`i18n.py` は逆向き（日本語しか言えないもの）しか
  数えていないので、どの物差しにも映っていなかった
* **型どおりの言い回し** ―― 「〜することができます」「必要があります」
  「エラーが発生しました」。いまは 0 件で、**入り込んだ日に鳴る見張り**

①②は**天井で見る**（`i18n.py` の `TUI_CEILING` と同じ作法）。いまの数を
天井に書いてあるので、増えたら落ちる。**減らすのは触った面から少しずつ、
天井も一緒に下げる。**

### ㋒ 桁 ―― 日本語でしか出ない

`widths.py` は「字数で画面の幅を測っているところ」を挙げる。
**`render.rs` の中では `chars().count()` をひとしく疑う** ―― ここは画面を
描くファイルで、ここの「長さ」はたいてい桁のことだから。文字の位置
（カーソルの桁、選択の範囲、伏字の数）は桁ではないので、`WAIVED` に
**行そのものと理由**を書いて外す。

そして `tui-drive.py` の⑥が**全角の片割れ**を数え、⑧が**使っている途中で
窓の大きさを変える**（41 桁から 200 桁まで7通り、一覧・トグル・ヘルプを
開いたまま）。

**「行の桁数が端末幅ちょうどか」で見ない。** 最初そう書いて、枠の無い行
（キー案内・状態行・シェルの中身）を 14 件の「桁くずれ」として並べた ──
短いのが当たり前の行だった。見るのは行の長さではなく**セルの対**:
①全角の次に別の字が書かれている ②空のセルの前が全角ではない。この二通りしか
崩れ方は無い。

**落ちないことも、桁と同じくらい機械で見る。** `:redraw` は
`Terminal::clear()` → `ESC[6n`（カーソル位置の問い合わせ）を通る。答えが
2 秒で返らないと crossterm は Err を返し、それを `?` で上げると **cian が
終わる**。答えない端末は珍しくないし、細い回線の向こうならなお遅い ──
**サーバ相手の道具が、画面を消せないことを理由に終わってはいけない。**
掃引の pty が `ESC[6n` に答えていなかったので見つかった（本物の端末は
答えるので、手元では出ない）。**手元で出ないものを出すのが、この道具の役目。**

### ㋓ 断られたら ―― 管理者権限のとき

`tui-drive.py` の⑦が、書き込めないディレクトリで新規作成とリネームを試す。
見るのは2つ:

1. **何かが出るか** ―― 黙って何も起きないのが一番わるい
2. **理由が出るか** ―― `anyhow` の `Display` はいちばん外の文脈しか刷らない。
   `rename A -> B` とだけ出て `Permission denied` は鎖の中に残る。
   **二つのパスと、失敗したという語が一つも無い知らせ**は、成功の報告に読める。
   `crate::util::why(&e)` が鎖を1行ずつ返す

Windows では ACL なので形が違う（管理者でも阻まれる。答えは昇格ではなく
`robocopy /B`）。ここで見ているのは**知らせ方**であって、権限の仕組みではない。

## ④ 検査を足したら、必ず変異テスト

**「指摘が消えた」ではなく「検査が黙った」を、この家では5回やっている。**
壊した版で鳴るのを見てから戻す:

```bash
cp crates/cian-tui/src/toggles.rs /tmp/toggles.bak
#   ↑ **cp で戻す。`git checkout` は作業を食べる**
# …わざと壊す…
python3 scripts/kotoba.py        # 鳴るか
cp /tmp/toggles.bak crates/cian-tui/src/toggles.rs
git diff --stat                  # 戻ったか
```

**足すときだけでなく、他所を直したときも黙る。** 件数が急に減ったら、
直ったのか壊れたのかを確かめる。

## ⑤ 直したら

```bash
cargo test -q --workspace > /tmp/t.out 2>&1; echo "exit=$?"
cargo clippy -q --workspace --all-targets -- -D warnings > /tmp/c.out 2>&1; echo "exit=$?"
```

**パイプ越しの終了コードは最後のコマンドのもの。** `cargo test | tail` の 0 を
cargo の 0 と読んで「全部緑」と言い、実際は2件落ちていたことがある。
要約したいなら出力をファイルへ落として、終了コードは別に見る。

そして **括ったものが再び分かれないよう、テストを1つ足す。**

## 報告の仕方

* **実行して観測したことと、推論しただけのことを分けて言う。** 落ちたテスト・
  飛ばした手順は丸めない
* **測っていないものは「測っていない」と言う。** 目視で「きれいでした」は無し
* 直したものは、**直った画面**を出す（`tui-drive.py -- キー` の最後の画面、
  `drive.js` の `shot:名前@セレクタ`）

## してはいけないこと

* **彼の指定を、後のパスで自分の美意識で消す。** 枠線を1回直して自分で戻し、
  同じ指摘を二度させたことがある。見た目の作り直しでも**状態表示は機能**。
  消す前に訊く
* **文言をまとめて書き換える。** 天井は「増やさない」ための線であって、
  「一括で直せ」という指示ではない。cian の声は彼の声で、僕の趣味ではない
* **出た候補を機械的に全部直す。** 意図的な使い分けを潰す（`audit.py` の
  `TERM_OK` / `PLURAL_OK` に理由が書いてある）
* **ペイン／枠／パネル、シェル／端末を混ぜる。** 揃えて「きれいにする」と
  意味が死ぬ
