## 本物の Windows で動かして（2026-11-28）

`~/workspace/edge-vm` の仮想環境（QEMU + HVF の Windows 11）で、CI が作った
`cian-tui-win-x64.exe` を動かしました。**Windows そのものは、手元から届きます。**

| # | 何が | どうなった |
| --- | --- | --- |
| S8 | 配る exe が、素の Windows で起動しない | **画面に何も出ないまま終了します。** 終了コードは `-1073741515`（`0xC0000135` ＝ DLL が見つかりません）です |

| S9 | 起動直後のお知らせが、Windows Terminal を「legacy console」と呼ぶ | **本物の Windows Terminal で出ます。** 「`wt cian-tui` で起動し直してください」と、壊れていないものを直すよう案内していました |

**原因は `VCRUNTIME140.dll` です。** Visual C++ の再頒布可能パッケージに入って
いるもので、Windows の素の状態にはありません。会社の PC には別のアプリが置いて
いったものがあるため、これまで表に出ませんでした。

**直し方は静的に結び付けることです**（`.cargo/config.toml` の `crt-static`）。
検査は `scripts/winstart.py` で、exe を**走らせずに**読み、再頒布が要る DLL を
取り込んでいないかを見ます。CI が資材を上げる前に当てます。

**S9 の原因は、環境変数だけで見ていたことです。** `WT_SESSION` は Windows
Terminal が**自分で**プログラムを起動したときにしか付きません。Windows 11 の
既定では、exe を叩くと conhost が Windows Terminal へ引き継ぐため、
**本物の Windows Terminal でも印が1つも付きません**（仮想環境で `WT_SESSION`・
`WT_PROFILE_ID`・`TERM_PROGRAM` のすべてが空であることを確認しました）。
いまは描いている相手の窓の種類（`ConsoleWindowClass` かどうか）で判定します。

**S10 の原因は、塗り直しの条件です。** 起動の表示は時計で消えますが、画面の
塗り直しは入力・大きさの変化・シェルの出力でしか起きません。**時計で消える絵は、
誰かが塗り直さないと消えません。** 起動の表示が出ているあいだは毎回塗り、
消えた最初の1回も塗るようにしました。検査は `scripts/tui-drive.py` の ⑩ で、
**何も送らずに9秒待って**、表示が消えていることを見ます。

> **注意**
> この種類の故障は、実行して初めて分かるものでした。仮想環境を使う前は
> 「Windows は手元で確かめられない」としていたため、**配る資材が起動するか
> どうかを、一度も確かめていませんでした。**

## ツールそのものの誤り（記録）

**最初の版は偽の合格を出しました。** エンジンは進捗などの行も送るため、
最初の1行を返事として読むと、終わっていない要求を「返りました」と報告します。
実際に `/dev/zero` のチェックサムが 0.03 秒で合格になっていました。
`id` が一致する行だけを返事とみなす形に直しました。

**2番目の版も空振りしました。** `hash` と `du` は要求の `path` を見ず、ペインの
カーソルが指すものを処理します。カーソルを置かずに `path` だけ渡していたため、
何も測っていませんでした。一覧から行番号を調べ、`cursors` を渡す形に直しました。

**3番目は、記録ファイルの検査そのものでした。** `scripts/requests.py` は
`(?s)(?=.*A)(?=.*B)` の形の検査を先読みごとに切り分けて当てますが、切り分けの
ときに**逃がした括弧（`\(`）を括弧として数えていました**。そのため先読みの
切れ目がずれ、書いたものとは別の正規表現を当てたまま緑になっていました。
記録ファイルには同じ形が 14 行ありました。深さを数えるときに逃がした文字と文字クラスの
内側を飛ばす形に直し、**直したあとも 14 行すべてが守られていること**を確認して
います（隠れていた破れはありませんでした）。

**4番目は、動作検証の準備そのものでした。** 端末版を建てるつもりで
`cargo build -p cian-tui` を実行していましたが、`cian-tui` という名前の実行
ファイルを作るのは `cian-bin` です。そのため端末版の検査が、3つ前のコミットの
実行ファイルを相手にしたまま緑になっていました。準備で `--bin cian-tui` を
建て、**焼かれたコミットが HEAD と一致するかを確認する**段を足しました。

> **注意**
> この4つはどれも「検査が何も報告しない」種類の誤りです。ツールを足したときは、
> **わざと壊して検知されることを確かめてください。**
