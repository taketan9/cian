# 動作検証の計画 ── 何を、どのツールで、どの順で確かめるか

この文書は、cian が実際に動くかどうかを確かめる**手順**です。確かめた結果は
ここには書きません。見つけたものは [sweep-findings.ja.md](sweep-findings.ja.md) に、
直したものは [`gui/REQUESTS.ja.md`](../gui/REQUESTS.ja.md) に記録します。

計画の狙いは2つです。**走らせられるものは全部走らせること**と、
**走らせられないものを名前で言うこと**です。後者を書く理由は、「確かめました」が
どこまでを指すのかを読む側が判断できるようにするためです。

## 1. 検証は、ひとつのコマンドで始めます

```bash
python3 scripts/verify.py
```

`scripts/verify.py` は新しい検査ではありません。既にある検査とツールを、
準備と順番つきでまとめて走らせるツールです。

| 走らせ方 | 何をするか |
| --- | --- |
| `python3 scripts/verify.py` | 準備をしてから全部を順に走らせます |
| `python3 scripts/verify.py --list` | 何を走らせるかだけを表示します。走らせません |
| `python3 scripts/verify.py --prepare` | 準備だけを実施します |
| `python3 scripts/verify.py kotoba 窓版` | 名前の一部が一致する段だけを走らせます |
| `python3 scripts/verify.py --self-test` | わざと失敗する段を混ぜ、このツールが赤を赤と報告するかを確かめます |

**各段の出力はファイルに落とし、終了コードは別に受け取る仕組みです。**
`cargo test` の出力を `tail` に通し、`tail` の終了コードを cargo の結果と
読み違えて「全部緑」と報告した事故があるためです。記録は
`~/.cache/cian-verify/` に段ごとの名前で残ります。

## 2. 準備はツールが実施します

検証を始める前に、人が何かを用意する必要はありません。`prepare()` が次の5つを
揃えます。既に揃っている場合は、そのまま使います。

| 揃えるもの | 無い場合にどうなるか |
| --- | --- |
| pty の仮想環境（`pyte` を含む） | 端末版を本物の pty で動かす検査が走りません |
| 窓版の依存（Electron） | 窓版の検査が1行も走りません |
| AI の mock 設定（`auth_mode = "mock"`） | AI の経路を、接続先なしで端まで通せません |
| エンジンと端末版のビルド | 窓版・注入・リモートの検査が、古い実体を相手にします |
| 建った実体が、いまの HEAD のものかの確認 | 古い実行ファイルを測ったまま、全部が緑になります |
| 居残りの Electron の終了 | 前回の窓版が残っていると、互いを終了させ合います |

**居残りの Electron を終了させる対象は、この作業ツリーのものだけです。**
対象を広く指定して、利用者が開いていた別のアプリケーションの画面を終了させた
ことがあるためです。

**仮想環境と mock の設定は `~/.cache` に置く仕組みです。** `/tmp` は macOS の
掃除で消えるため、2回発生しています。

**`cargo build -p cian-tui` では、端末版の実行ファイルは建ちません。**
`cian-tui` という名前の実行ファイルは `cian-bin`（パッケージ名は `cian`）が
作り、`cian-tui` はそれが使うライブラリです。取り違えると、検査は古い実行
ファイルを相手にしたまま緑になります。そのため準備では `--bin cian-tui` で
建て、**焼かれたコミットがいまの HEAD と一致するかを確認する仕組み**です。
作業中は木が汚れているのが普通なので、`-dirty` は許します。

## 3. 検証は4つの層に分かれています

上から順に実施します。下の層だけを実施しても、結果を信用できません。

| 層 | 何を見るか | 落ちた場合の意味 |
| --- | --- | --- |
| ① 建つか・通るか | `cargo test --workspace` と、警告を禁じた `cargo clippy` | ここが赤いうちは、他の層の結果に意味がありません |
| ② 機械による検査 | 文言・桁・名前の揃い・設定の網羅・依頼の記録ファイル・設計書の名前 | 利用者に見える部分の約束が破れています |
| ③ 本物で動かす | 本物の pty・本物のキーとクリック・本物の SFTP サーバー・わざと詰まらせた相手 | 実際の操作が通りません |
| ④ 届かないもの | 走らせていないものを、毎回最後に名前で表示します | ここに挙がったものは、実機で確認が必要です |

**②の一覧は、分類していない検査があると走る前に失敗する仕組みです。**
`scripts/` に増えた検査が一覧から落ちて、通知なしに走らなくなるのを防ぐためです。
実際に `scripts/settingscover.py` が、2か所の一覧の片方から落ちていました。

**②は見つけたものを勝手には走らせません。** `scripts/` には公開済みの
リリースに資材を足すツール（`scripts/release-asset.py`）もあり、「見つけたから
走らせる」と事故になるためです。走らせないものには、外した理由を書いています。

## 4. ③で、何を本物の相手に対して動かすか

| ツール | 本物の相手 | 落ちた場合に疑うところ |
| --- | --- | --- |
| `scripts/tui-drive.py` | 本物の pty（起動・枠・マウスの当たり・一巡・桁） | 端末版の描画と入力 |
| `scripts/sweep.py` | 本物の pty。コマンドを一つずつ叩きます | 名乗っているのに答えないコマンド、そこで固まるコマンド |
| `scripts/inject.py` | 名前付きパイプ・応答しないポート・2GB の疎ファイル・大量の項目 | 要求の処理に時間の上限が無いところ |
| `scripts/remote.py` | 自分専用に立てた SFTP サーバー | リモートペインの接続・転送・表示するパス |
| `gui/drive.js` | 本物のキーとクリック（Electron） | 窓版の画面と操作 |
| `gui/drive.js --commands` | 同上。パレットのコマンドを一つずつ | 押す道が無いコマンド |
| `gui/drive.js --values` | 同上。設定の値 | 設定が画面に戻らないところ |
| `gui/drive.js --ai` | mock の AI（網も鍵も使いません） | 説明からコマンドを生成する経路 |
| `gui/drive.js --ai-real` | **本物のモデル** ── Claude CLI か Ollama | 答えが返り、プロンプトに載るまで |
| `~/workspace/edge-vm` の仮想環境 | **本物の Windows 11** | Windows でしか出ないもの（起動そのものを含みます） |

**リモートペインは、手元で本物のサーバー相手に通せます。** macOS には `sshd` と
`sftp-server` が最初から入っており、管理者権限なしで高いポートに自分専用の
ものを立てられる仕組みです。そのため「手元に SFTP サーバーが無い」は理由に
なりません。

**`gui/drive.js --ai` は経路だけを確かめます。** 本物の接続先が実際に答えるか
どうかは、ここでは分かりません。

## 5. ここから届かないもの

**この表は 2026-11-28 に短くなりました。** 仮想環境の Windows と、手元で本物の
答えを返す AI が入ったためです。以前ここに「Windows そのもの」「IME」
「AI の本物の応答」と書いていましたが、**どれも手元で確かめられます。**

| 届かないもの | どこで確かめるか |
| --- | --- |
| 会社の環境そのもの（社内の経路・共有フォルダ・権限） | 実機のみ。仮想環境は素の Windows です |
| 配る資材が自分の版を正しく名乗るか | `scripts/buildstamp.py` に資材を渡します。CI が staging の直後に実施します |
| 見た目の良し悪し | **利用者が画像で判断します。** 新規実装と改修のあとは画面を撮って提示します |

**届くようになったもの:**

| 以前の書き方 | いまの確かめ方 |
| --- | --- |
| Windows そのものは見られない | 仮想環境で CI の資材を動かします。**初回で、素の Windows では起動しないことが出ました** |
| 配列と IME は実機のみ | 仮想環境の Windows に本物のキーを送ります（`vmctl.py`、`LAYOUT=us`） |
| AI の本物の応答は実機のみ | Claude CLI と Ollama に訊きます（`--ai-real`） |

> **注意**
> 「手元では確かめられない」と書く前に、本当に届かないかを確認してください。
> 端末版もリモートペインも、長いあいだ「手元では無理」として扱われていましたが、
> どちらも実際には手元で動かせました。

## 6. この計画に、まだ無いもの

| 無いもの | なぜ要るか |
| --- | --- |
| 状態の掛け合わせ（[sweep-plan.ja.md](sweep-plan.ja.md) の第4段） | 画面を1つ開くと作業中の内容が消える型の不具合は、単独の操作では出ません |
| 上限の無い待ちの一覧（同じ文書の第2段） | 固まる箇所を、注入の前に静的に数えるためです |
| 配る資材そのものの起動確認 | 手元のビルドは通っても、梱包した資材で起動するかは別の話です |
